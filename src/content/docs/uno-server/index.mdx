## Description

A UNO card game server written in Go. Manages rooms, player hands, and game actions.
Game state is persisted as JSON files per room (`<roomID>.json` for cards, `<roomID>.data.json` for action state).

Current behavior:
- JSON bodies are written without setting a Content-Type header, so responses
  are actually served as `text/plain; charset=utf-8` even though the body is JSON text.
- JSON error responses use the envelope:
```json
  {"error": "<message>", "status": "bad", "resp": ""}
  ```
- HTTP status is 200 even on errors.
- `/action` returns an empty body on success.

## Servers

- `http://localhost:8080` - Local development server

## Paths

### `/action`

#### `GET`

- Summary: Play a card / perform a game action
- Description: Validates and processes a card play for the given player in the room.
Checks card ownership and legality (color/number/wild match), updates the
hand, discard pile, and turn, and applies the Skip turn effect.
On success the response is HTTP 200 with an empty body.

Error handling as currently implemented:
- `roomID` and `player` parse errors are silently ignored (the last `Atoi`
  error, for `card`, wins).
- If `card` is missing or non-numeric, the response has status "ok" with
  the Atoi error text in `resp`.
- Other errors are returned as the usual envelope with status "bad".
- Operation ID: `playAction`

### `/fetchAction`

#### `GET`

- Summary: Get current game action state
- Description: Returns the room's action data as a string produced by Go's `fmt.Sprint`
on the `GameActionData` struct, in this field order:
```json
{ban plusTwo color clockWise turn lastCard plusFour}
```
`color` is only set when the room is created; it is not updated when a
card is played.
- Operation ID: `fetchAction`

##### Parameters

| Name | In | Required | Type | Description |
| --- | --- | --- | --- | --- |
| `roomID` | query | yes | integer | Room ID |

##### Responses

###### `200`

Game action data returned, or the room data file was not found.

###### `text/plain`

####### Schema

- Summary: string
- Description: JSON text; on success `resp` contains the `fmt.Sprint` rendering of the action data.

### `/fetchPlayerCards`

#### `GET`

- Summary: Get a player's cards

containing Go's representation of an integer slice, e.g. `[202 303 405]`.
- Operation ID: `fetchPlayerCards`

### `/newRoom`

#### `GET`

- Summary: Create a new UNO room and deal cards
- Description: Creates a new game room for 2-4 players. Each active player is dealt 7 cards.
A random integer in [0, 999] is used as the room ID. The first card of the
remaining deck is used as the initial `lastCard`; the current implementation
leaves that card in the deck and keeps only it in `repo`.
- Operation ID: `newRoom`

##### Parameters

| --- | --- | --- | --- | --- |

##### Responses

###### `200`

###### `text/plain`

####### Schema

## Schemas

### `GameActionData`

#### Details

- Summary: object
- Description: Logical fields of `<roomID>.data.json`. `/fetchAction` returns this struct
via `fmt.Sprint`, not as a JSON object.

| Property | Type | Required | Description |
| --- | --- | --- | --- |
| `ban` | boolean | no | Initialized to false; currently never updated (Skip is implemented by advancing `turn`). |
| `clockWise` | boolean | no | Initialized to true; currently never updated (Reverse is not implemented). |
| `color` | integer | no | Color derived from the initial `lastCard` via its hundreds digit: 100 -> 0, 1xx -> 1 (Red), 2xx -> 2 (Yellow), 3xx -> 3 (Blue), 4xx -> 4 (Green), 5xx -> 5 (Wild). Not updated when cards are played. |
| `lastCard` | integer | no | The last played card ID. |
| `plusFour` | integer | no | Initialized to 0; currently never updated. |
| `plusTwo` | integer | no | Initialized to 0; currently never updated. |
| `turn` | integer | no | Current player's turn (1-4). |
